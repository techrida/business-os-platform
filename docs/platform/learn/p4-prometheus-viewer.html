P4 Prometheus study viewer

This viewer scrapes the real current P4 API and worker, built from P4 source with the shared development viewer change.

Open query and graph viewer · Inspect scrape targets

Try it

  1. Query up{phase="p4"}. Both bos-api and bos-worker should equal 1.
  2. Switch to graph view and select the last 15 minutes. Startup includes a brief API-down interval.
  3. Try process_resident_memory_bytes{phase="p4"} to compare process memory.

Targets: api:9464 and worker:9465, isolated P4 containers on the preserved P4 backend network. A value of 1 proves scraping works; it does not prove all business dependencies work.

Verified on the dev machine, 16 November 2026

Both targets UP, instant up query and graph range query succeeded. Host loopback viewer: 127.0.0.1:19094. API and worker have no published host ports. Production compose is unchanged. No reseeding or migrations were run.

Limits

The saved P4 identity endpoint is stopped, so worker identity reconciliation fails. Full login, PDF rendering, mail and scanning were not tested or brought up for this viewer. A new restricted development field-encryption key enables API startup; it cannot decrypt any fields encrypted under an older key. No business flows or stored encrypted data were changed. Another physical private network device has not been tested. This stateless viewer is private to the private network and has no separate product login.

Runtime ownership

Compose project bos-p4-viewer uses image bos/api:prometheus-p4. Runtime config and credentials remain untracked under .dev/prometheus-p4. It reuses preserved bos-p4qa database and queue containers. Do not delete their volumes. The viewer lease is user service bos-p4-prometheus-lease.service, which waits for the actual Prometheus container to exit. Restart that lifetime lease after container recreation. Grafana is not installed.
